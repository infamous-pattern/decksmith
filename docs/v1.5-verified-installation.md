# V1.5 installation and update

**V1.5 published October 16, 2026.** Fresh public downloads passed signature,
hash and archive verification. Use [v1.5.1](https://github.com/infamous-pattern/decksmith/releases/tag/v1.5.1)
for Fedora Workstation 44. The [retained V1 guide](v1-verified-installation.md)
remains available for recovery. The [V1.5.0 manual guide](v1.5.0-verified-installation.md) and release are also retained.

This guide applies to Fedora Workstation 44 x86_64, GNOME/Wayland, with Stream Deck +
and standard 15-key MK.2. Other models and distributions retain their separate
[support limits](v1.5-release-review.md). It supplements the unchanged signed
archive's older `INSTALL.md`; it does not replace or edit signed files.

## Simplified Installer — recommended

The [Simplified Installer](install-decksmith.md) handles dependency setup, signed
downloads and per-user installation. It never starts/restarts controls, enables
login startup or installs system USB rules. Experimental OS pins stay separate.

## Manual installation

Install dependencies from Fedora's trusted repositories:

```sh
sudo dnf install git gh curl python3 python3-gobject python3-pillow python3-cairo gtk4 libadwaita librsvg2 glib2 systemd systemd-libs pulseaudio-libs pulseaudio-utils wireplumber
```

Use GitHub CLI **2.102.0 or newer** for workflow/ref verification. The simplified
helper offers a reviewed, pinned temporary copy when the distribution CLI is too
old. Do not skip signature checks to work around an old or unavailable verifier.

Run the following as your regular desktop user. Review the source and verifier;
initial trust comes from that reviewed source and trusted CLI, not a downloaded
release helper authenticating itself:

```sh
git clone https://github.com/infamous-pattern/decksmith.git decksmith-v15-verifier
cd decksmith-v15-verifier
git checkout --detach 4891555b388f1806ca0cda909d77af6dbd77a8ee
mkdir downloads
for file in decksmith-linux-x86_64.tar.gz decksmith-install.py package_io.py INSTALL.md SHA256SUMS candidate.json attestation.json; do
    curl --fail --silent --show-error --location \
        --proto '=https' --proto-redir '=https' --tlsv1.2 \
        --connect-timeout 10 --max-time 180 --retry 3 \
        "https://github.com/infamous-pattern/decksmith/releases/download/v1.5.1/$file" \
        --output "downloads/$file" || exit 1
done
python3 -I scripts/verify-install.py downloads \
    --source-sha 4891555b388f1806ca0cda909d77af6dbd77a8ee \
    --bundle downloads/attestation.json
```

Expected: bundle `1.5.1-9d7719a68ed2`, 496 manifest files, archive SHA-256
`dc69ac03cd76210894a5aaf6337aa15496e8cb849a199e1e754521924464c28a`.
Verification authenticates all six subjects against the exact source, repository,
workflow, ref and hosted-runner policy, then checks hashes and archive contents.
Stop if it fails. Signed `candidate.json` retains its original pending text; the
release review separately records promotion of unchanged bytes.

Before updating, save and close the editor and retain a complete backup:

```sh
decksmith-manage backup
```

For an existing installation, record the backup path and previous build. After
verification, install with the same helper:

```sh
python3 -I scripts/verify-install.py downloads \
    --source-sha 4891555b388f1806ca0cda909d77af6dbd77a8ee \
    --bundle downloads/attestation.json --install
```

The installer retains the previous release, takes another configuration backup,
preserves saved data/login preference and does not activate controls. Reopen
Decksmith, close competing controllers, then deliberately stop/start Background
controls to load the update. On a fresh installation choose Start; login startup
is off until you enable it. The device chooser selects which independent layout
you edit. A newly added MK.2 gets its own defaults rather than copying the Plus.

## Fresh-install defaults

Fresh installations and newly added devices use Maker’s Mark: Sans, Small, White
text, Transparent · page color background, Bottom labels, Transparent label
background and 85% icons. The Home page’s bottom-left logo key opens Decksmith’s
GitHub repository (Plus key 5; MK.2 key 11). On Plus Home, Mute uses key 6.
Saved profiles are preserved; updates do not replace them with starter layouts.

## Optional USB access for Plus and MK.2

If a connected device is inaccessible, review existing Stream Deck access rules
first. The archive's `70-decksmith-plus.rules` covers only the Plus. The following
rule grants access to the active desktop session for just the Plus (`0fd9:0084`)
and standard MK.2 (`0fd9:0080`); it does not grant world-writable access or include
other Elgato devices. This rule passed `udevadm verify`; installing it remains an
administrator action, separate from the per-user installer.

Save this reviewed content as `decksmith-supported.rules`:

```udev
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="0fd9", ATTRS{idProduct}=="0084", TAG+="uaccess"
SUBSYSTEM=="usb", ATTRS{idVendor}=="0fd9", ATTRS{idProduct}=="0084", TAG+="uaccess"
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="0fd9", ATTRS{idProduct}=="0080", TAG+="uaccess"
SUBSYSTEM=="usb", ATTRS{idVendor}=="0fd9", ATTRS{idProduct}=="0080", TAG+="uaccess"
```

An administrator can add it without overwriting an existing file:

```sh
sudo sh -c 'umask 022; set -C; cat > /etc/udev/rules.d/70-decksmith-supported.rules' < decksmith-supported.rules &&
sudo udevadm control --reload-rules
```

If that file already exists, stop and review it instead of replacing it. After a
successful reload, unplug/reconnect the affected Deck. Keep the other connected
if it is in use. Do not run Decksmith itself with sudo.

## Recovery and downgrade

Keep the previous package and complete pre-upgrade configuration/device-store
backup together. V1.5's compact store uses manifest version 2. Before a downgrade,
save edits, close the editor and stop both Decksmith background services. Preserve
the newest state separately, then restore the matching complete earlier store and
its package/integration. A merge restore can leave newer store files that were
absent from an older backup; binary-only rollback or restoring individual layouts
is not a complete downgrade procedure. Seek a reviewed recovery plan if the
backup/build pair is uncertain rather than deleting or merging saved data.

The release tests cover the recorded paired-store restoration and guest rollback
cases, not every old engine/schema combination. Normal same-build reinstallation
and preserved user files are separate from arbitrary schema downgrade support.
The retained V1 release and experimental previews remain available for recovery.
