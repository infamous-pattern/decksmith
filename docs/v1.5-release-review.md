**Maintainer accepted this coverage and its documented limits on October 16, 2026,
and authorized publication of the unchanged qualified candidate as V1.5.**

operation, independent saved layouts/pages/brightness, shared audio/media and
microphone control, the simplified editor, and selectable dial gauges. Linked
navigation remains deferred after V1.5; general plugins and system monitors remain
V2 work. [Release notes](v1.5-release-notes.md) describe the user-facing scope.

The first quiet attempt stopped when Bluetooth phone playback appeared; it is not
included. The retry observed no uncorked playback. Brave was active at all 121
loaded sample points; other application playback inventories were retained. One
Plus page transition settled on the next 200 ms readiness recheck. This does not
measure electrical-input-to-pixel latency. No observer changed Decksmith services,
audio routing, volume or layouts. Stable sampled memory does not exclude a
long-term leak. The combined 5% target was met in these two samples; the broader
normally-below-1% daemon goal and numeric display timing remain follow-up work.

A fresh exact-version OSV query returned no matches across 277 distinct locked
crate/PyPI versions from the app and receipt-backed installed companion. This is
not a complete security audit; it excludes distribution libraries and unknown
vulnerabilities. Installed integrity covers all 491 app files and 75 companion
files, including the separately rebuilt native companion's build receipt.

## Retained limits and recovery

- Supported baseline: Fedora Workstation 44 x86_64, GNOME/Wayland; one Plus and
  one standard 15-key MK.2 physically qualified. No all-model certification.
- Existing Debian 13, Ubuntu 26.04 and Pop!_OS 24.04 COSMIC previews remain separate
  experimental downloads. This release does not replace/rebuild them or expand
  official platform support. Fedora 45 and openSUSE remain test environments.
- Homebridge remains experimental and uses a separate managed companion. Core
  provenance does not authenticate or install that companion; retain existing
  settings/bindings and distinguish its separate receipt and live acceptance.
- Navigation and GNOME foreground-application rules remain independent per device.
  Linked navigation, general double-press/hold assignments, Dial Stacks, Action
  Wheel, Now Playing, wallpaper and sticky keys are not delivered here.
- Enlarged text may need a wider window. The monochrome caption fallback does not
  provide full-color/compound emoji shaping. The icon-only Layout options menu
  remains less discoverable than a visible label.
- The device store uses manifest version 2. Downgrading requires the matching
  complete pre-upgrade configuration/device-store backup and previous build.
  Binary-only rollback and merging a few configuration files are insufficient;
  do not imply arbitrary old-engine/schema rollback was qualified.
- The pre-existing default/no-hardware compile gap remains documented. The release
  package and quality gates use the hardware/all-features configuration.

The server storage prerequisite is resolved: both copied trees were byte/metadata
verified, all ten guests booted and shut down, backups were rechecked, original
paths were retained through persistent mounts, and only then were old duplicate
trees removed. The initial core-limit launch failure and four root-owned lock
files were corrected through normal-user verification and a targeted ownership
repair. Original failure records remain retained. This is infrastructure recovery,
not a Decksmith runtime fix or wider OS certification.

## Publication decision and procedure

The maintainer chose **Publish V1.5 with documented limits**, accepting the
explicitly identified carried-forward checks and retained limits above. This
authorizes documentation synchronization to Gitea and sanitized GitHub, stable
`v1.5.0` publication of the unchanged qualified files, and Fedora installer/README
promotion only after fresh public-download admission. It does not authorize
another desktop installation.

A private copy of the proposed Fedora installer pin, regenerated shell helper
and matching README/manual links passed all 114 installer/security tests (one
skipped) on the AI server. Experimental OS pins were unchanged. This preparation
did not change the public helper or create a release.

Approved delivery procedure:

1. Synchronize reviewed documentation; retain the exact candidate identities.
2. Tag the accepted public candidate source and the corresponding canonical
   source, with the same source tree. Publish a stable GitHub release with the
   original six signed subjects and retained signing bundle, without replacement
   builds or edited signed metadata. Preserve V1 and the experimental previews.
3. Fetch every public asset into a fresh directory. Reverify all seven accepted
   hashes, six signatures, source/workflow identity and archive admission. Stop if
   any byte, signature or identity check fails.
4. Only after fresh-download admission, promote the Fedora simplified-installer
   pin and README/manual-guide links to V1.5. Preserve experimental OS pins and
   the existing walkthrough. Check regenerated installer consistency and the
   targeted installer tests before source publication.
5. Record delivered source/tag identities and the fresh-download result. Keep
   the previous desktop build and matching complete configuration backup.
