# V1.5 candidate review

The signed candidate `1.5.0-8c0783ad4bf8` has completed its recorded qualification.
The [final release review](v1.5-release-review.md) identifies repeated and
carried-forward evidence, installation/recovery details and retained limits.
The maintainer approved promotion on October 16; public-download verification
and installer/README promotion remain delivery steps. V1 and experimental preview
pins remain in place until those checks pass.

## Included behavior

- Stream Deck + and the 15-key Stream Deck MK.2, including simultaneous control
  with independent saved layouts, pages and brightness. A newly enrolled MK.2
  starts with its own defaults; the existing Plus layout is imported once.
- Device-addressed editor saves and previews, preserved custom assignments and
  previous-layout recovery, with a simpler Action/Appearance editor and visible
  scroll cues. Monochrome fallback makes supported emoji captions recognizable.
- Shared native audio/media actions and feedback across the two devices, meters
  derived from effective saved targets, and unavailable targets kept separate.
- Shared microphone holds: Mute cancels all active holds; the last release
  returns to Muted. Page/disconnect fencing prevents a stale hold from reopening
  the microphone while preserving a valid hold on the surviving device.
- Dual-arc volume/activity gauges and a single-arc activity presentation with
  volume percentage, retaining Classic bar and assigned dial actions.
- Permanent background operation with paired lock, suspend, hot-plug, quit
  blanking and login startup. Shared providers and discovery avoid unnecessary
  unchanged work; input polling and microphone maintenance remain in place.

Linked navigation, general independent double-press/hold assignments, Dial Stacks,
Action Wheel, Now Playing, wallpaper and sticky keys are excluded. General plugin
hosting/catalog capabilities and plugin system monitors are deferred to V2.

## Qualification already recorded

The October 15 development checkpoints record physical Plus/MK.2 controls,
independent pages/brightness, shared audio/media/microphone behavior, USB
isolation/recovery, lock, suspend, quit/relaunch, login, paired editor saves and
previous-layout restoration, keyboard focus and Orca. Tests span successive
development packages; they are carried-forward evidence, not proof that every
interaction was repeated on the final signed artifact.

The latest optimized development package passed 342 Rust tests (six deliberately
ignored), strict Clippy, isolated package provenance/hardening/paired backup
restoration, and physical controls/Homebridge plus bidirectional USB recovery.
Its finite observations averaged 2.497% combined CPU of one core over five quiet
minutes and 4.507% over ten loaded minutes. Loaded daemon RSS stayed at 45.63 MiB.
These are saved-layout observations, not universal budgets or a matched V1
comparison. See the [coordinator checkpoint](checkpoints/2026-10-15-coordinator-optimization.md).

## Support and retained limits

- Qualification baseline: Fedora Workstation 44 x86_64, GNOME/Wayland, one Plus
  and one MK.2. Additional identical devices and other models are not established
  by this pair's physical acceptance.
- Debian 13, Ubuntu 26.04 and Pop!_OS 24.04 COSMIC retain their separate existing
  experimental previews. Fedora 45 beta and openSUSE remain test environments.
  This candidate does not rebuild those previews or expand official OS support.
- Homebridge remains experimental and uses its separate managed companion.
  Existing companion settings/bindings must survive the update. Core candidate
  attestation does not authenticate a separately installed companion archive.
- Automatic application pages use the GNOME reporting integration and each
  device's own rules. Navigation is independent; there are no linked workspaces.
- Numeric visible-response timing remains deferred. A finite below-1% daemon
  idle result does not establish the normally-below-1% goal across configurations.
- Enlarged text may require a wider window. Full-color/compound emoji shaping
  is not supplied by the monochrome caption fallback.
- The compact device store uses manifest version 2. A downgrade requires the
  matching complete configuration/device-store backup; a binary-only rollback
  or a merge of configuration files is insufficient.
- The existing default/no-hardware compile configuration has a documented gap;
  release quality gates and packages use the hardware/all-features build.

## Candidate admission and promotion

1. Review intended source, version and documentation; exclude private lab output,
   guest details and generated artifacts. Run current quality, installer/editor
   and isolated paired-runtime checks on the exact source snapshot.
2. Commit reviewed source and synchronize the identical tree to Gitea and the
   separate sanitized GitHub history. Record both identities. Source publication
   and candidate attestation are distinct from publishing a stable release.
3. Dispatch the pinned Fedora 44 candidate workflow at the reviewed public commit.
   Retain its original six candidate files and signing bundle. Verify checksums,
   manifest/source identity and all attestations against that exact workflow,
   source digest and main-branch ref, rejecting self-hosted signers.
4. Prefer AI-server isolated source/package/recovery and native VM checks in
   parallel where capacity permits. Preserve original guests/backups and normal
   scheduled jobs. A VM does not replace physical USB/audio/accessibility tests.
5. Before desktop installation, protect editor work and retain the previous build
   plus a verified whole-store configuration backup. Qualify the exact candidate
   on both physical Decks; record repeats, carried-forward coverage and limits.
6. Present the exact artifact, completed gates and limits for explicit release
   approval. Publish unchanged accepted bytes only after that approval, then
   verify fresh public downloads before changing installer pins and README links.

The supported V1 and existing preview downloads remain available throughout.
